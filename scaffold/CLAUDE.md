# Инструкции для ИИ-агентов

Этот репозиторий — база знаний о проектах пользователя. Используй его, чтобы быстро получить контекст перед задачей, а не только код целевого репозитория.

Весь контент лежит в `{{docsDir}}/`. Кода здесь нет — веб-UI (repodocs) живёт отдельно и открывает эту папку через свой `config.json`.

## Как читать

1. Начни с [INDEX.md](INDEX.md) — одна таблица со всеми проектами/областями/ресурсами (title, type, status, stack, summary, путь). Обычно этого достаточно, чтобы понять, какой проект тебе нужен.
2. Открой `README.md` конкретной папки (например `{{docsDir}}/projects/<slug>/README.md`) — там frontmatter + разделы "Что это", "Текущий фокус", "Архитектура", "Ключевые решения".
3. При необходимости — дополнительные файлы в той же папке, включая подпапки-подпроекты (`architecture.md`, `api.md`, `journal.md`, вложенные модули вроде `backend/`). Не читай их все подряд без нужды — README обычно ссылается на релевантные.
4. [{{docsDir}}/resources/glossary.md]({{docsDir}}/resources/glossary.md) — сквозной словарь людей, терминов, кодовых имён (если заведён). Загружай, если встречается незнакомая аббревиатура или имя.

## Схема данных

Frontmatter-поля описаны в [{{docsDir}}/schema/frontmatter.md]({{docsDir}}/schema/frontmatter.md). Ключевое:
- `status` говорит, стоит ли вообще предлагать что-то по этому проекту (`archived`/`idea` — не в работе).
- `updated` — если дата старая, содержимое могло устареть; не полагайся на него слепо для быстро меняющихся систем.
- `summary` — одна строка сути, используй её для быстрой навигации по INDEX.md вместо открытия каждой папки.

## Как писать/обновлять

- Один файл = одна тема. Не дублируй информацию между файлами — ссылайся через relative markdown-ссылки (`[текст](../other-project/README.md)`).
- При создании нового проекта/области/ресурса используй соответствующий шаблон из `{{docsDir}}/templates/` и сразу заполни frontmatter.
- Если у проекта появляются логически обособленные подсистемы/модули — оформляй их подпапками внутри карточки (а не отдельными карточками), в UI это отображается деревом.
- При значимом изменении в проекте обновляй `updated` в frontmatter и, если есть, добавляй запись в журнал (`journal.md`) с датой.
- После добавления/переименования/архивации папки — обнови [INDEX.md](INDEX.md) (вручную или `npm run build-index` в repodocs; UI делает это автоматически при сохранении README).
- При любой значимой правке карточки пройдись по разделу "Обязательно при правке" в [{{docsDir}}/schema/review-checklist.md]({{docsDir}}/schema/review-checklist.md). Если пользователь просит "проверить доки" — используй весь чек-лист, не только этот раздел.
- Никогда не пиши реальные секреты (пароли, токены, ключи, DSN с паролем) в файлы вне `{{docsDir}}/local/`. Если нужно сослаться на секрет — укажи, где он лежит (`{{docsDir}}/local/<file>`), не само значение.
- Завершённые/неактуальные проекты переноси в `{{docsDir}}/archive/<slug>/` целиком (папкой), не удаляй. Для точечного удаления одной карточки есть корзина в UI (`{{docsDir}}/trash/`, 30 дней на восстановление) — не удаляй файлы напрямую, если для этого предназначен UI.

## Общие правила

- Пиши на языке, на котором ведётся база, если пользователь не просит иначе.
- Держи README проекта кратким и актуальным ("справка, не документация" — детали техники выноси в отдельные файлы той же папки).
- Не изобретай статус/стек/связи, которых нет в исходных данных — если непонятно, оставь поле пустым/`unknown` и спроси пользователя, а не гадай.
