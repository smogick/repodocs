# Схема frontmatter

Есть две разных схемы — не смешивай их.

1. **Карточка** (`README.md` внутри папки сущности) — полная схема ниже, обязательна, из неё строится `INDEX.md`.
2. **Отдельный файл внутри карточки** (`architecture.md`, `api.md`, `team.md` и т.п.) — необязательная лёгкая схема, см. [ниже](#схема-для-отдельных-файлов-внутри-карточки). Не дублирует и не заменяет карточку — это метаданные конкретного документа, а не проекта.

В UI (`repodocs-ui`) обе схемы редактируются через "карандашик" в панели над редактором — вручную писать YAML не обязательно.

## Схема карточки

```yaml
---
title: Мой проект
type: project            # project | area | resource
status: active            # active | paused | idea | archived
stack: [go, react, postgres, redis]
owner: me
created: 2025-01-01
updated: 2026-08-30
tags: [antiddos, admin-panel]
links:
  repo: ""
  tracker: ""
  docs: ""
summary: Одна строка о том, что это за проект.
---
```

## Поля

- **title** — человекочитаемое имя проекта/области/ресурса.
- **type** — `project` (продукт/проект с целью и результатом), `area` (постоянная зона ответственности без конца), `resource` (справочный материал: домены, сервера, доступы).
- **status** — текущее состояние. `idea` — ещё не начато, `active` — в работе, `paused` — приостановлено, `archived` — завершено/неактуально (см. [../archive/README.md](../archive/README.md)).
- **stack** — технологии, если применимо. Пустой список `[]`, если нет.
- **owner** — ответственный за карточку.
- **created / updated** — даты в ISO-формате `YYYY-MM-DD`. `updated` обновляется вручную при значимых изменениях — это основной сигнал "свежести" для агента.
- **tags** — свободные теги для кросс-поиска (нижний регистр, kebab-case).
- **links** — репозиторий, трекер задач, вики/доки. Пустая строка, если нет. Конвенции: `repo` — URL или локальный путь к основному репозиторию (один; если сервисов несколько — остальные перечисли в тексте); `tracker` — URL или код проекта в трекере задач.
- **summary** — одна строка, используется при генерации `INDEX.md` и в UI-списке. Пишите так, чтобы агент понял суть проекта не открывая файл.

## Схема для отдельных файлов внутри карточки

Три поля, все необязательные — если нет ни одного, файл вообще не должен иметь frontmatter-блока (пустой блок хуже, чем его отсутствие):

```yaml
---
status: draft      # draft | active | superseded | archived
updated: 2026-09-06
summary: Одна строка о том, что это за документ.
---
```

- **status** — своё для конкретного файла, не путать со статусом карточки. `draft` — черновик/предложение, ещё не решено; `active` — актуальный, действующий документ; `superseded` — заменён другим файлом (укажи каким, в тексте); `archived` — сохранён для истории, не актуален.
- **updated** — когда в последний раз реально правили содержимое (не карточку целиком).
- **summary** — если название файла не говорит само за себя.

Это прямо закрывает пункт "черновик без статуса" из [review-checklist.md](review-checklist.md#обязательно-при-правке-карточки) — не нужно вписывать "Статус: черновик" текстом в начало файла, для этого есть frontmatter-поле и панель редактирования в UI.

## Правило про секреты

Реальные пароли, токены, ключи, строки подключения — **никогда** не пишутся в файлы внутри `projects/`, `areas/`, `resources/` (они попадают в git). Храните их в `local/` (в `.gitignore`) и в документах ссылайтесь на них по имени: "см. `local/<project>.env`", не вставляя значение.
